# 内置：为目标项目生成约定文档（AGENTS.md）

## 优先级

<!-- 建议 P0：约定文档是其它任务获取真实约束的前提，越早生成越好。 -->

- [x] P0 — 紧急，阻塞线上（最高）
- [ ] P1 — 高，本迭代必须
- [ ] P2 — 中，有空就做
- [ ] P3 — 低，锦上添花（最低）

## 问题描述

对本任务 `frontmatter.project` 指定的目标项目做一次只读体检，然后在**目标项目根目录**生成一份约定文档（文件名取 `config/配置.md` 的 `convention_file`，默认 `AGENTS.md`）。这份文档供后续所有在该项目执行的任务读取，让它们知道该项目的真实环境、技术栈、构建命令与编码约定，而不必依赖配置的通用默认约定。

**只生成/补全约定文档，不要改动目标项目的业务代码。**

## 关联文件

<!-- 相对路径按 project 解析。文档路径由约定文件名决定；其余为探测依据（只读）。 -->

- `AGENTS.md`（要生成/补全的约定文档；路径与文件名以配置 convention_file 为准）
- `README.md`（探测依据，只读）
- `pom.xml` / `package.json` / `build.gradle` / `Makefile` / `pyproject.toml`（按实际存在情况探测，只读）

## 验收标准

- [ ] 已探测目标项目根目录，列出实际存在的项目类型与关键配置文件
- [ ] 约定文档已生成在目标项目根目录，包含以下章节：**项目概述 / 环境要求 / 技术栈 / 构建与测试命令 / 编码约定 / 注意事项**
- [ ] 文档内容来自对目标项目真实文件的观察（配置清单、源码结构、README），不是凭空猜测；无法确定的项标注「未检测到，需人工补充」
- [ ] 构建/测试命令从项目自身配置推断（如 `pom.xml`、`package.json`、脚本文件），并在文档中写出可直接执行的完整命令
- [ ] 若约定文档已存在：在保留原有正确内容的前提下补全缺失章节，不覆盖、不推翻已有约定
- [ ] 未改动目标项目的任何业务代码或配置文件（除约定文档本身）

## 备注

- 探测顺序建议：先看根目录文件清单 → README → 各语言构建清单 → 源码目录结构 → CI 配置（如 `.github/workflows`、`Jenkinsfile`）
- 生成的约定文档要具体、可执行，避免空泛套话；命令要能直接复制运行
- 若目标项目不是 git 仓库或未配置 project，按通用规则报 blocked
