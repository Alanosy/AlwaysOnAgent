# 内置：探测目标项目环境与结构

## 优先级

- [ ] P0 — 紧急，阻塞线上（最高）
- [ ] P1 — 高，本迭代必须
- [x] P2 — 中，有空就做
- [ ] P3 — 低，锦上添花（最低）

## 问题描述

对 `frontmatter.project` 指定的目标项目做一次**只读**体检，摸清它的目录结构、技术栈、依赖与构建方式，把结论写进本任务文件的「总结」section。**不改动目标项目的任何文件**——这是一个纯探测任务，用于在动手前快速了解一个陌生项目。若需要把结论固化成约定文档，请改用「生成项目约定文档」内置任务。

## 关联文件

<!-- 均为只读探测对象，相对 project 解析。 -->

- `README.md`（若存在）
- 构建/依赖清单：`pom.xml` / `package.json` / `build.gradle` / `requirements.txt` / `go.mod` / `Cargo.toml` 等（按实际存在情况）
- 源码根目录与主要模块目录
- CI 配置：`.github/workflows/` / `Jenkinsfile` 等（若存在）

## 验收标准

- [ ] 列出目标项目根目录的一级结构（目录与关键文件）
- [ ] 识别出项目类型与技术栈（语言、框架、构建工具），依据具体配置文件，无法判断则注明
- [ ] 找到并写出可直接执行的构建命令与测试命令；找不到则注明「未检测到」
- [ ] 指出潜在风险或注意事项（如多模块、特殊环境要求、生成代码目录、禁止改动的第三方源码）
- [ ] 目标项目文件零改动（本任务只读）
- [ ] 结论已写入本任务「总结」的「做了什么 / 注意事项」中

## 备注

- 全程只读，不要执行会修改项目或生成产物的命令（如 build）；如需验证构建请用 dry-run 或仅读取配置推断
- 探测不到 project 或路径不存在时，按通用规则报 blocked
